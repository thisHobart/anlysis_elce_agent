## P2 方案草案

[P2 新闻事件与电价分析技术方案](phase2-news-price-analysis-proposal.md)采用测试先行：新闻采集由外部 API 负责，当前外部适配器仅为占位符；六个研究问题已在合成夹具上全部跑通。当前另有 10 条真实来源开发集、独立金标准、规则基线报告，以及可注入模型网关的结构化抽取器。尚未完成的是真实模型资格运行、独立盲测集和外部 API 适配器。P1/P2 使用独立领域契约，边界测试双向守卫；跨阶段可获得性由 P2 在导出前完成，P1 的 `available_at` 只是提示而非行级门禁。

## 后续主题的记录规则

- P2/P3 仅作为研究主题标签，不代表已经确定的开发顺序、组件名称或交付日期。
- P2 已有独立方案草案；状态、已确认边界、未决项和阶段门禁以该草案为准，评审结论再回写系统基线文档。
- 数据源、事件结构、抽取方法、统计方法、评估门槛和模块改造需要经过单独技术方案评审后，才能写成“决策”或“开发任务”。
- 不再维护独立的“长期路线”文档；阶段计划形成后，应在独立提案中说明状态、依据和出口条件，避免把设想混入当前架构事实。

## 维护约定

1. 新增或重命名文档时同步更新本页和根目录 `README.md`。
2. 架构或跨模块接口变化时同步更新架构设计、图集源文件和图集校验结果。
3. P1 实现状态只写入功能说明和验收文档，不在多份总览中复制测试数字。
4. 候选方案使用“待研究”或“待确认”，不得写成已实现或已采用。
5. 提交前检查 Markdown 相对链接，并运行 `docs/architecture-diagrams/validate.ps1` 校验图集。
