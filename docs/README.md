## 状态冲突时如何判断

按以下优先级判断，避免把历史报告当成当前事实：

1. 当前代码、契约和可复现测试结果；
2. [P2 进展状态](phase2-status.md)或[P1 验收记录](phase1-acceptance.md)；
3. 当前实现专题文档；
4. 技术方案中的目标和门禁；
5. 带明确日期的测试报告与历史运行记录。

测试报告中的模型名、测试数量和通过率只适用于报告注明的日期、代码版本、语料与端点配置。后续代码变更不会自动继承旧验收结论。

## 维护约定

1. 每份文档只承担一种主要职责：基线、当前状态、设计方案、实现专题或验证记录。
2. 当前状态只在阶段状态/验收记录中维护；专题文档引用它，不复制容易过期的结论。
3. 验证记录必须写明日期、输入、版本、结果和适用范围；不得改写为无日期的当前事实。
4. P2/P3 是研究主题标签，不自动表示已批准的产品能力或交付顺序。
5. 新增、删除或重命名文档时同步更新本页和根目录 `README.md`。
6. 提交前检查 Markdown 相对链接；修改图集后运行 `docs/architecture-diagrams/validate.ps1`。
