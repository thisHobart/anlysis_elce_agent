# 会话级地区电价数据源

桌面端右侧数据面板只有一个地区选择按钮。一次选择只改变当前研究会话；历史会话和同时保存的其他会话仍保留各自的数据源、缓存与数据指纹。

## 当前范围

`configs/region_databases.yaml` 当前只登记山东。15 分钟实时电价从主表读取；同口径小时表用于补齐主表之前的历史，因此当前电价研究轴从 2025-11-01 开始，而不是只从 2026-01-01 开始。小时价格按“小时结束点”展开到该小时内的四个 15 分钟点。查询强制使用只读事务，并同时按业务时间和数据创建时间截止到本次读取时刻。`hour=24,min=0` 被规范化为次日 `00:00`，其他非法 24 点表达会被隔离。

实际外生变量包括统调负荷、发电总出力、非市场化机组出力、新能源出力、风电、水电（含抽蓄）、光伏、正备用和负备用；预测变量包括负荷、发电出力、风电、光伏和水电。多数实际变量从 2025-01-01 开始，但联合分析的共同时间范围仍受电价起点约束。表结构说明中虽然列有火电类型，当前数据库对应类型实际为 0 行；程序仍会在每次取数时检查该类型，在有记录后自动纳入，但不会用“总发电减其他电源”的方式冒充火电数据。

历史气象以 ERA5 小时表为主，GFS 小时表只补 ERA5 缺失的历史小时；预测气象来自 GFS 小时表。两者均在各自小时内部前向展开到 15 分钟，不跨越缺失小时。实际和预测各包含气温、80 米风速、云量、太阳辐射和小时降水。逐日 GFS 表保留在取数详情中，但不直接混入 15 分钟研究轴。

读取成功后，电价、实际影响因素和预测影响因素分别原子写入当前会话独立的 Parquet 文件，再进入现有的数据质量、可用时间、指纹和不可变快照流程。右侧面板只显示前四项摘要，完整列表通过“查看全部影响因素”菜单展开。数据库密码、地址与用户名不会进入会话文件、研究产物或界面详情。

## 在聊天中选择分析时间

取数卡显示的是数据库当前可用的完整范围。用户可以在随后问题里给出两个完整日期，限定本次会话实际参与计算的数据，例如：

- `仅分析 2026-01-01 到 2026-03-31 的电价与水电关系`
- `分析区间 2026年4月1日 00:15 至 2026年6月30日 23:45`
- `恢复全部时间范围`

未写具体时刻时，开始日期从 `00:00` 起算，结束日期包含全天；时间按地区配置的市场时区解释。方案生成前会先裁剪目标和影响因素，方案卡及右侧数据面板显示实际进入分析的交集。短区间内没有记录的影响因素会留下数据质量状态并退出变量筛选，不会阻止仍有电价数据的研究。

## 增加地区

在 `configs/region_databases.yaml` 的 `regions` 数组中增加一项，至少指定：

- 稳定的 `region_id` 和显示用 `label`
- 市场名、省份筛选值、时区和数据频率
- 凭据环境变量前缀
- 实际电价表、可选小时历史表、字段映射和类型筛选值
- 可选的 `actual_series` 与 `forecast_series`（名称、表、类型值和数值列）
- 可选的历史气象表、预测气象表、逐日气象表及变量字段

然后在程序同目录的 `.env` 中增加该前缀对应的 `HOST`、`PORT`、`USER`、`PASSWORD` 和 `NAME`。例如配置使用 `VPP_EXAMPLE_DB_FEATURE` 前缀时，实际变量名为 `VPP_EXAMPLE_DB_FEATURE_HOST` 等。也可以让 `PRICE_RESEARCH_REGION_DATABASES` 指向运维管理的地区目录文件。

新增地区会自动出现在同一个按钮中。地区目录不保存凭据；正式环境应使用只读账号。
