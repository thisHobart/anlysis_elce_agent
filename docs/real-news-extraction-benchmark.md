## 1. 为什么没有删除旧合成集

旧 `tests/fixtures/news_price/` 仍负责可控的统计回归：去重、更正、`as_of`、时间泄漏、注入效应和证据哈希。
真实新闻没有配套反事实价格，若直接替换旧集，将无法判断事件—价格方法是否恢复了已知答案。

新增 `tests/fixtures/news_realistic/` 取代旧集作为**抽取准确率证据**。测试时不访问网页，避免来源页面修改导致 CI
漂移；每条记录只冻结标题和短摘录或轻度压缩摘录，并保留原始 URL、来源层级、发布时间精度、抓取时点与内容哈希，
不保存整篇报道。

## 5. 主要问题

1. **高：分类词表只覆盖测试句式。** 中文真实表述“跳闸”“重新并网”“负荷创纪录”以及全部英文记录均被静默归为无关。
2. **高：实体规则只识别 `TEST_*` 和大写代码。** 中文电厂、机组、区域与自然语言资产名无法抽取。
3. **高：时间契约和解析器过窄。** 真实新闻大量只有日期、当地时刻、时间范围或“高温前”等模糊表达；当前仅接受 ISO 时刻和少量中文相对日时刻。
4. **高：量值固定为 MW 且语义混杂。** 万/亿千瓦需要换算；需求水平、出力水平、损失出力和变化量不能共用一个 `capacity_mw`。
5. **高：多事件只在命中多个模板后才隔离。** 当前连事件类别都没有命中，因此复杂新闻没有进入复核区，而是静默丢失。
6. **中：方向被事件类型硬编码。** 例如低风意味着可再生供给下降并可能形成上行压力，现有 `renewable_supply_change` 规则只能表达“预计增加/向下”。

没有产生误报不等于安全：系统把 9 篇含运行事件的新闻当成无关信息，真实运行会形成严重漏报。

## 6. 结构化模型开发集历史结果（schema 1.1.0）

2026-09-03 使用 Cherry Studio API Server 调用 `vertexai:gemini-3.8-flash`。Cherry 2.0.2 没有把
OpenAI `json_schema` 或 Function Calling 完整转换给该模型，因此本次使用明确标记的 `prompt_json`：
schema 随系统消息发送，响应由本地 Pydantic 严格校验，报告标记 `schema_enforcement=local`。

| 指标 | 实际 | 判定 |
|---|---:|---|
| 随机 schema 探针 | 3 / 3 | 通过 |
| 可抽取事件召回率 | 2 / 2 = 100% | 通过 |
| 应隔离新闻召回率 | 7 / 7 = 100% | 通过 |
| 无关新闻正确率 | 1 / 1 = 100% | 通过 |
| `unknown` 比率 | 0 / 10 = 0% | 通过 |
| 逐案完整准确率 | 8 / 10 = 80% | 按旧门槛通过；按当前 100% 门槛失败 |
| 证据完整性 | 100% | 通过 |

R05、R06 的事件类型、相关性、容量和时间均正确，未完整命中来自实体标准化差异：R05 输出区域
`Britain`、资产 `AGRs`，金标准要求区域 `Great Britain` 且不记录泛称资产；R06 输出一个复数资产名称，
金标准要求拆成 Unit 1 和 Unit 2，并要求区域 `QLD`。这些差异应通过独立的实体规范化层处理，不应放宽
新闻证据校验。

## 6.5 盲测集与多趟一致性闸门的历史结果

`tests/fixtures/news_holdout/` 是 2026-08—09 抓取的第二套真实语料，**未参与任何 Prompt、schema 或阈值
调整**，与开发集不重叠。首次单趟盲测暴露了三类问题，其中两类是真实缺陷：

| 现象 | 性质 | 处理 |
|---|---|---|
| 区域一会写 `辽宁`、一会写 `辽宁电网`；电网名一会填区域、一会填资产 | 契约未定义归属，模型只能掷硬币 | 受控词表 + 规范化层，见[实现说明](structured-news-extraction.md) |
| 一句话两次破纪录，只报了后一次 | 漏报（静默丢失） | 多趟一致性闸门 |
| 机组异常停运统计被判为“无关新闻” | 误判，且“无关”不进复核区 | 多趟一致性闸门 |

五次重复运行显示，问题不是均匀噪声：**10 篇里 9 篇每次模型原始输出哈希都不同**（`temperature=0` 也如此），
但最终判定只有 5 篇会变——本地契约闸门吸收了大部分抖动，剩下的抖动全部落在契约未定义或原文本身有歧义处。
当时 `quarantine_recall` 在 66.7%–100% 之间摆动，导致**是否合格本身随机**（5 次中 3 次合格）。

当时修复后（规范化层 + 3 趟一致性闸门），同一盲测集重复 3 次：

| 指标 | 单趟 5 次（修复前） | 3 趟一致性 3 次（修复后） |
|---|---|---|
| 可抽取事件召回率 | 100%（稳定） | 100%（稳定） |
| 应隔离新闻召回率 | 66.7% – 100%（摆动） | 83.3%（三次相同） |
| 无关新闻正确率 | 100%（稳定） | 100%（稳定） |
| `unknown` 比率 | 0%（稳定） | 0%（稳定） |
| 逐案完整准确率 | 50% – 70% | 90%（三次相同） |
| 总判定 | 3 次合格 / 2 次不合格 | **3 次全部合格** |

区域措辞与区域/资产归属仍会在趟间变化（`辽宁` 与 `辽宁电网`、电网名填区域还是资产），但规范化后判定完全一致，
R01 与 R03 三次全部通过——这正是规范化层要达到的效果：原文照记，身份不变。

**指标稳定不等于逐案稳定。** 当时三次运行中 R05 与 R08 仍在摆动，且恰好互补（一个通过时另一个失败），
`quarantine_recall` 因此都停在 5/6。这是巧合，不应解读为这两条已经稳定。基准现已用 `--repeat N`
逐案比对并输出 `metric_stability_is_incidental` 标志，把这种巧合直接标出来，不再靠人去发现。

加入当时的两道确定性闸门（拒绝存疑的“无关”、时间锚点计数）并把三趟一致性设为默认值后，盲测集重复 3 次：

| 指标 | 单趟 5 次 | 3 趟一致性 3 次 | **加确定性闸门 3 次** |
|---|---|---|---|
| 可抽取事件召回率 | 100% | 100% | **100%** |
| 应隔离新闻召回率 | 66.7%–100% | 83.3% | **100%** |
| 无关新闻正确率 | 100% | 100% | **100%** |
| 逐案完整准确率 | 50%–70% | 90% | **100%** |
| 总判定 | 3 合格 / 2 不合格 | 3 次合格 | **3 次合格** |
| 摆动案例 | R01 R02 R03 R05 R08 | R05 R08 | **无** |

上述 `metric_stability_is_incidental` 和 `unstable_verdicts` 结论属于旧实现。当前实现已取消“日期数量直接决定隔离”，改为核对重复事件措辞并保留有效候选；因此这些结果不能沿用，必须重新运行。
R08 由 `disputed_irrelevance` 拦下（模型仍判无关，但正文含 `100MW` 与“停运”），R05 三次都进隔离区。
R01/R02/R03 的区域与资产措辞仍在趟间变化，但规范化后判定完全一致——原文照记，身份不变。

成本：每篇 3 次模型调用，实测 38.0 秒/篇（10 篇 × 3 次重复 = 90 次调用，1141 秒）。

## 7. 下一步门禁

当前规则抽取器继续作为显式模板回归基线，不再通过堆关键词扩展。结构化模型抽取代码边界已经完成，
详见[结构化模型新闻抽取实现说明](structured-news-extraction.md)。当前进度为：

1. **已完成**：模型原生结构化输出、字段级证据和失败隔离；
2. **已完成**：时间精度及原文绝对时间/组合时间/相对时间契约；
3. **已完成**：量值、单位、水平/变化/损失/恢复语义及确定性单位换算；
4. **已完成**：一篇文档多个事件候选、同文证据隔离和单次抽取缓存；
5. **待重跑**：使用 schema 1.2.0 和严格门槛重新评估开发集与盲测集；
6. **已完成**：建立不参与 Prompt 调整的盲测集并重复运行（单趟 5 次、三趟一致性 3 次）；
7. **已完成**：实体规范化层与多趟一致性闸门，消除措辞漂移造成的身份漂移与判定摆动；
8. **已完成**：两道确定性闸门。一致性闸门只能抓住**不稳定**的错误，模型稳定判错时它看到的是“一致”；
   `disputed_irrelevance` 拒绝证据不足的“无关”终局判定，`ambiguous_multi_event` 要求正文每个时间锚点
   都被某个事件认领。盲测集上两者各拦下一个此前长期判错的案例；
9. **已完成**：成本与延迟记录（报告 `cost` 段）与逐案稳定性测量（`--repeat N` 的 `stability` 段）；
10. **待完成**：金标准复核。盲测集的期望标签由单人判定，`gold_reason` 已随逐案结果输出，需第二人独立复核；
11. **待完成**：扩大语料。开发集只有 2 条“应抽取事件”，`extractable_event_recall` 因此以 50% 为步长跳变，
    单个案例翻转就能越过任何阈值——该指标目前过于粗糙，不适合单独作为门禁；
12. **待完成**：更大规模人工复核与更长期的成本观察。
