## 1. 方案总览

本系统需要在模型输出不可控、不可复现的前提下，产出可复现、可审计的研究结论。全部技术选型均由这一矛盾派生。

| # | 要达成的目的 | 技术挑战 | 采用的技术与机制 | 阶段 |
|---:|---|---|---|---|
| 1 | 自然语言问题转为可执行的分析计划 | 模型输出格式不稳定，可能夹带推理文本与虚构参数 | Function Calling 强制结构化输出，配合计划编译与 fail-closed 校验 | P1 |
| 2 | 分析计算可复现、可重放 | 模型生成的分析代码无法版本比对与审计 | 白名单原子函数注册表与确定性执行器，基于 numpy / pandas / scipy / statsmodels | P1 |
| 3 | 领域研究遵循固定证据顺序 | 提示词约束可被后续对话稀释或绕过 | 版本化 YAML 研究协议与本地授权函数集，构成 Skill | P1 |
| 4 | 支持人工审批中断与崩溃恢复 | 长流程状态易丢失，审批点需要可暂停可续跑 | LangGraph 的 interrupt / resume 与 SQLite checkpoint | P1 |
| 5 | 结论判定不依赖模型主观评价 | 模型自评不稳定，随版本漂移 | 基于结构化证据的确定性评估器，输出四态决策 | P1 |
| 6 | 全链路溯源与防陈旧执行 | 数据、代码、参数在流程中可能漂移 | 数据指纹、计划版本、工具版本、结果哈希与 manifest | P1 |
| 7 | 私有数据零部署使用 | 数据不得离开本地，用户无运维能力 | PySide6 桌面应用与 PyInstaller 打包 | P1 |
| 8 | 新闻文本转为可检验的事件证据 | 抽取依赖模型，不可复现，且易与统计证据混同 | 事件表落盘固定 + 置信度准入过滤 + 下游检验全部走注册函数 | P2 |

| 10 | 事件效应的统计识别 | 窗口重叠、样本稀疏、多重检验膨胀 | 事件窗口 + 安慰剂窗口 + 多重检验校正写入协议不变式 | P2 |
| 11 | 时序防泄漏的样本外评估 | 随机切分、折外信息回流是隐性错误 | 滚动切分器主动拒绝非法切分 + 折内变换管道 | P3 |
| 12 | 预测实验的可复现与可比较 | 模型含随机性，实验组合空间大 | 种子参数化并纳入指纹 + `ExperimentSpec` 组合契约 | P3 |
| 13 | 跨实验的证据积累 | 多轮实验导致验证过拟合与重复劳动 | 以研究包指纹为索引的实验记录库 + 测试集独立解锁 | P3 |

## 3. 第一阶段技术议题详述

### 3.1 自然语言问题转为可执行分析计划

**目的**　用户以自然语言提出研究问题，系统须将其转换为参数完整、变量合法、可直接执行的分析计划，且转换过程的失败必须显式暴露而非静默降级。

**方案**　由 `MainResearchAgent`（`app/research/agent/orchestrator.py`）判断当前回合属于方法讨论、新建方案、修订方案、结果解释还是执行确认，`EDASubagent`（`app/research/agent/subagents/eda.py`）在当前 Skill 授权范围内选择具体函数并形成结构化计划。结构化计划固定使用 Function Calling 产出，不接受自由文本解析。

**机制**　模型接入集中于 `app/llm`：`ModelGateway`（`gateway.py`）定义 Agent 自有的类型化消息、结构化输出、文本输出与 Function Calling 契约，`ResearchModelGateway`（`openai_compatible.py`）把这些对象交给显式选择的 Chat Completions 或 Responses 适配器，`factory.py` 为主 Agent 与 EDA Subagent 注入同一网关。`tools`、`tool_choice`、消息角色和结构化 schema 属于核心协议，端点拒绝或未返回原生调用时直接报告配置不兼容，不再切换 API，也不解析自由文本或提示词 JSON。`compat.py` 只允许移除温度、Provider 自动添加的推理控制和 `parallel_tool_calls` 等非核心字段，并保留非标准 HTTP 响应信封修复。端点仍返回 `reasoning_content`、reasoning block 或 `<think>` 内容时，默认策略（`VPP_LLM_THINKING_POLICY=strip`）丢弃思考内容后继续，严格策略（`reject`）维持 fail-closed。模型返回无效调用、空回复或未授权内容时流程暂停并提示重试。

**选型理由** 〔待确认〕　候选方案 A 为提示词约定 JSON 格式并由正则或 JSON 解析器提取，实现成本低，但格式违约率随对话轮次上升，且无法区分模型意图错误与格式错误；候选方案 B 为自定义 DSL，须自行实现解析、校验与错误提示，成本高于直接复用 Function Calling 的参数 schema。选择 Function Calling 的关键收益在于参数 schema 由服务端参与约束，违约在调用侧即被捕获。关闭 thinking 是以推理质量换取输出稳定性与延迟可控的取舍，其前提是复杂判断已由确定性组件承担，模型不需承担长链推理。

**代价与边界**　方案质量受模型对 Skill 描述与参数 schema 的理解能力限制，更换模型供应商或 API 形式须重新验证消息角色、结构化输出与 Function Calling 兼容性。自动化测试只能覆盖本地边界行为，真实端点能力仍须独立验收。

### 3.2 保证分析计算可复现与可审计

**目的**　同一数据与同一计划两次执行须产出完全一致的结果，且任一数值均可回溯至确定的函数版本与参数。

**方案**　建立包含 30 个原子研究函数的工具注册表，按数据可用性核验、电价自身规律、外生变量质量、关系证据、可预测性准备度五类组织，全部基于 numpy、pandas、scipy 与 statsmodels 实现。模型只能选择函数与参数，不能提供实现。

**机制**　函数名的单一事实来源是 `app/research/tools/catalog.py` 中的 `ResearchFunctionName` 字面量联合类型；实现按主题分布于 `app/research/tools/eda/` 的 `price.py`、`exogenous.py`、`relationships.py`、`dependence.py`、`drivers.py`、`segments.py`、`structure.py` 等文件。工具执行链如下。

```text
模型 Function Call
→ EDAPlan
→ Planning Compiler (planning/compiler.py)
→ ToolRegistry (tools/registry.py)
→ ToolPolicy (tools/policy.py)
→ ToolExecutor (tools/executor.py)
→ numpy / pandas / scipy / statsmodels 确定性函数
→ ToolResult
```

关键约束包括工具名须命中注册表且版本精确匹配，变量名须来自当前研究配置，目标序列不能冒充外生变量，每个函数在一个计划中最多出现一次而多变量多滞后多分段通过批量参数表达，`data_quality` 由编译器强制加入，模型不能提供函数路径、任意 Python、SQL 或未注册参数。负价与尖峰作为市场现象保留，不做静默删除或截尾。相关性、互信息、Granger 前置性与分组差异仅作为描述性证据，不自动等同于因果或样本外预测增益。

**选型理由** 〔待确认〕　候选方案 A 为沙箱 Python 解释器，表达力最强，但生成代码不可复现、不可版本比对，审计时须逐段阅读模型代码，与可复现性优先的质量目标直接冲突；候选方案 B 为受限 DSL，仍须自研解析与安全校验，且用户与审计者需要学习额外语法。固化原子函数库把安全边界从运行时前移至注册时，使越权在编译阶段即被拒绝，是三者中审计成本最低的方案。

**代价与边界**　新增分析能力必须先扩充函数库，模型无法即兴组合，函数库覆盖度成为产品迭代速度的瓶颈。该代价在进入 P3 后将更为明显：预测实验的组合空间远大于 EDA，逐一注册函数不可行，须以 `ExperimentSpec` 这类更高层的组合契约缓解（见 §4.5）。此外 `catalog.py` 以字面量联合类型枚举函数名，在函数数量继续增长后是否仍适合作为单一事实来源，须在 P2 开工前评估。

### 3.3 约束领域研究顺序而不依赖提示词

**目的**　电价研究存在客观的证据先后顺序，数据可用性核验未通过时不应进入关系分析。该顺序须由系统强制，不能因对话轮次增加而被稀释。

**方案**　将研究顺序、阶段目标、授权函数集合、函数规则与退出门槛写入版本化 YAML 研究协议，与 `SKILL.md` 共同构成 Skill。当前内置两个 Skill，Skill 与协议各自独立版本化。

| Skill | Skill 版本 | 协议 ID | 协议版本 | 授权函数数 | 适用范围 |
|---|---|---|---|---:|---|
| `price-exogenous-eda` | 3.2.0 | `electricity-price-evidence-ladder` | 2.2.0 | 30 | 电价与外生变量联合 EDA |
| `price-forecastability-audit` | 1.2.0 | `price-forecastability-ladder` | 1.2.0 | 14 | 仅有目标电价，或先判断电价自身可预测性 |

**机制**　`price-exogenous-eda` 的六层证据阶梯为：市场任务与预测时钟 → 数据质量与可获得性门禁 → 电价结构状态与记忆 → 驱动变量质量 → 关系稳定性 → 可预测性准备度。协议以三个字段承载约束：`invariants` 是任何计划都不得违反的不变式（如「正滞后固定表示 `feature[t-lag]` 与 `price[t]`」「目标与驱动平稳性 verdict 同为 unit_root 时同期相关按伪相关处理」），`stop_conditions` 是须停止而非降级的条件，`stages` 是分层的函数授权与退出门槛。模型只在协议授权集合内选择函数，不能通过提示词改变本地权限。外部 Skill 可经程序同级 `skills/` 目录或 `VPP_SKILL_PATHS` 加载，但不能注册新函数或执行任意脚本。

协议中一条值得单独指出的约束是「每条假设都必须能被本轮选择的函数判定」。它把研究问题的可判定性前置到规划阶段，使写不出对应函数的猜想在进入执行前即被拒绝，而非在评估阶段以「证据不足」收场。这条约束是 EDA 循环能够收敛的关键。

**选型理由** 〔待确认〕　候选方案 A 为将研究顺序写入系统提示词，实现最简，但提示词是模型的建议而非系统的约束，长对话中易被后续指令覆盖，且无法版本化比对；候选方案 B 为在代码中硬编码流程，约束强度足够，但每次调整研究方法都需要改代码并重新分发。YAML 协议在约束强度上等同于硬编码，在可维护性上接近提示词，同时天然支持版本号与 Skill 之间的横向扩展。

**代价与边界**　协议本身成为需要维护的资产，其表达能力决定了可支持的研究方法上限。Skill 与协议双版本号带来标注成本，文档引用须分别注明，历史上已出现过版本漂移。外部 Skill 的加载能力扩大了攻击面，故限定其不能注册新函数或执行脚本。

### 3.4 支持人工审批中断与崩溃恢复

**目的**　计划执行前必须获得用户审批，审批可能持续数分钟至数小时，期间进程可能退出。流程须能在中断点精确恢复，且审批事实不能被伪造。

**方案**　由单一 `ResearchLoopGraph`（`app/research/graph/workflow.py`）承载研究过程，使用 LangGraph 的 `interrupt` 暂停于审批点，`Command(resume=...)` 携带用户操作恢复，SQLite checkpoint 保存 Graph 权威运行状态，测试场景使用内存 saver。

**机制**　Graph 以 `ingest_user → main_agent` 为入口，经条件路由分派至 `resolve_skill → eda_subagent → validate_plan → prepare_approval → approval_interrupt`，审批通过后进入 `advance_tool → mark_tool_running` 的逐函数执行循环，最终经评估路由至 `prepare_evaluation_revision`（回到 `eda_subagent`）、`prepare_need_user`（进入 `user_interrupt`）或终止节点 `persist_stop` / `persist_failure`。状态、守卫与迁移分别由 `state.py`、`guards.py`、`migrations.py` 承载，过程叙述由 `narration.py` 生成。

方案审批同时校验方案 ID、方案指纹与审批事实三者，模型意图不能绕过审批。非法 action 不改变原 checkpoint，状态保持可恢复。规划失败、函数重试与崩溃恢复与已完成评估的 Iteration 分开计数。自动修订只能在原审批范围内收缩工具、变量或滞后，扩大范围必须回到用户门禁。Graph 事件、消息与运行历史有界保存，完整桌面轨迹由会话投影保留。

**选型理由** 〔待确认〕　候选方案 A 为自研状态机加数据库持久化，控制力最强，但中断恢复、部分执行、重试计数与状态迁移的正确性需要自行验证，而这恰是易出错且难以测试的部分；候选方案 B 为不做持久化，审批超时即丢弃，实现最简但与桌面长会话的使用形态冲突。选择 LangGraph 的核心理由在于 interrupt 与 checkpoint 是其原生语义而非附加能力，人在环审批这一需求被框架直接覆盖。

**代价与边界**　流程语义与框架版本耦合，当前依赖域锁定为 `langgraph>=1.2,<1.3`，跨次版本升级须重新验证中断恢复行为。`migrations.py` 的存在说明 checkpoint 兼容性已成为实际维护项。P3 引入多折实验后，单个节点的执行时长将显著上升，须确认长任务下的 checkpoint 写入时机与桌面端的进度反馈是否仍然可用。

### 3.5 结论判定不依赖模型主观评价

**目的**　研究结论的接受与否须由证据决定，同一批证据在不同时间、不同模型版本下应得到相同判定。

**方案**　由 `app/research/evaluation/eda.py` 中的确定性评估器依据结构化工具证据给出判定，模型不直接产出最终结论，仅负责解释已判定的证据。

**机制**　评估器检查数据是否足以支持当前研究、计划中的关键证据是否已产生、假设是否得到支持或不支持或证据不足、是否存在可在原审批范围内修订的问题、是否需要补充数据或用户确认、结论是否触及方法论固有限制，并输出 `accept`、`revise`、`need_user`、`reject` 四种决策。其中 `revise` 触发原审批范围内的有限自动修订，`need_user` 回到人工门禁。

**选型理由** 〔待确认〕　候选方案 A 为由模型阅读结果并给出结论，实现最简且表达自然，但同一批证据的判定不可复现，且模型倾向于给出肯定结论，与研究场景需要的保守判定相悖；候选方案 B 为完全由用户判定，判定质量最高但丧失自动修订与循环推进能力。确定性评估器的价值在于把可规则化的判断固化，把不可规则化的判断显式交还用户，即 `need_user` 这一态的存在意义。

**代价与边界**　评估规则的覆盖度决定了自动推进的比例，规则之外的情形一律退化为 `need_user`。当前评估器为单文件实现，规则集中于一处；P2 的事件研究判定与 P3 的实验晋级判定引入后，是继续扩充该文件还是按域拆分为多个评估器并共用一套决策契约，须在 P2 开工前决定。晚决定的代价是评估逻辑与 EDA 语义纠缠后难以剥离。

### 3.6 全链路溯源与防陈旧执行

**目的**　任一结论须可回溯至确定的输入、代码与参数，且方案审批之后输入发生变化时，系统须拒绝继续执行而非产出不一致的结果。

**方案**　对输入文件计算 SHA-256 指纹，对计划、Skill、协议、工具分别记录版本，对工具结果记录输出哈希，并在研究包 manifest 中汇总输入输出哈希、Git 版本与运行环境。

**机制**　数据层（`app/research/data/`）实现时间戳解析、时区统一、数值转换、非法记录识别（`loader.py`）、统一时间网格与目标外生变量对齐（`alignment.py`）、覆盖率与可获得性风险检查（`quality.py`）、对齐快照（`snapshot.py`）与字段推断（`inference.py`），输出对齐后的标准分析帧供规划、执行与评估复用。方案生成后文件被原地修改时，指纹校验失败并拒绝执行旧方案。`call_id` 与 `work_id` 配合数据指纹与输出哈希，实现执行溯源与确定性结果复用。单次研究产出的研究包结构如下。

```text
agent-<timestamp>-<fingerprint>/
├── report.md                桌面内置阅读器展示的主报告
├── methods.md               本轮方法、参数、判据、边界与证据位置
├── figures/*.svg            图表源文件
├── evidence/
│   ├── data_quality.json    数据质量证据
│   ├── eda_summary.json     完整结构化分析结果
│   └── agent_evaluation.json 评估结论与反馈
├── provenance/
│   ├── conversation.json   对话记录
│   ├── research_plan.json  计划、Skill、协议、版本与参数
│   ├── execution_trace.json 函数执行时间与结果引用
│   ├── research_loop.json  循环上下文
│   └── study_context.json  自动识别的数据与时间轴上下文
├── data/aligned_data.parquet 固定的对齐数据快照
└── manifest.json            输入输出哈希、Git 与运行环境
```

**选型理由** 〔待确认〕　候选方案 A 为仅记录报告与结果，存储成本最低，但结论无法重放，审计时只能相信报告；候选方案 B 为完整保存原始输入副本，可重放性最高但存储代价与数据合规风险显著。指纹加对齐快照的组合在可重放性与存储成本之间取得平衡，快照保证分析帧可复现，指纹保证原始输入的变更可被检出。

**代价与边界**　研究包体积随研究轮次线性增长，需要清理策略 〔待确认〕。指纹只能检出变更，不能恢复原始数据，故对齐快照是必需项而非冗余项。该结构在 P3 是实验记录库的天然索引基础（见 §4.6），设计上无需另建标识体系。

## 4. 第二、三阶段技术议题预研

以下条目尚未进入实现，给出的是技术路径与其取舍，用于在开工前锁定方向。每条的「选型理由」均标注 〔待确认〕。

### 4.1 新闻文本转为可检验的事件证据（P2）

**目的**　把非结构化新闻转换为可参与统计检验的事件记录，同时不破坏「计算可复现」这一质量属性第一优先级。

**方案**　新增 `EventExtractionSubagent`，与 `EDASubagent` 平级并共用 `ModelGateway`，输出经 Pydantic 契约约束的结构化事件表；事件表落盘为本地文件并纳入指纹体系，其后所有统计检验基于该固定事件表运行。

**机制**　三层隔离：其一，事件表的语义定位是**输入数据**而非**证据**，与用户提供的 CSV 处于同一层级，同样可被人工检查与修正；其二，抽取过程不可复现但抽取结果一经落盘即固定，因此「事件表 + 计划」的组合仍满足同输入同输出；其三，每条事件携带置信度，置信度只用于准入过滤而不参与加权计算——低于阈值的事件整条排除。

抽取字段至少包含：事件类型、涉及实体、地理区域、影响方向、强度分级、置信度，以及三个时间戳（见 §4.2）。

**选型理由** 〔待确认〕　候选方案 A 为关键词规则抽取，完全确定性且零模型依赖，但电力市场新闻的表达多样性高，规则维护成本随语料增长迅速上升，且漏报难以察觉；候选方案 B 为本地小模型微调，可复现性优于 API 调用，但需要标注数据与训练算力，与「桌面单机、无 GPU」的部署约束冲突；候选方案 C 为让模型直接读新闻并给出电价影响判断，绕过事件表，实现最简但把模型意见直接当作证据，同时违反 D1 与 D4，属于须明确排除的路径。

选择 A 与 B 之外的第三条路——模型抽取 + 结果固化——的核心理由是它把不可复现性限制在一次性的、可人工复核的产物上，而不是让它渗入每一次统计计算。这与 P1 中「模型选函数、代码算结果」的分工是同一个思路在文本域的应用。

置信度只做准入不做加权，理由是加权会把模型的主观不确定性混入统计量，使结论既不可复现也不可解释；准入过滤则把不确定性收敛为一个可审计的布尔判定，阈值本身作为计划参数纳入指纹。

**代价与边界**　抽取准确率无金标准，置信度由模型自评，其可信度存疑，须以小规模人工标注集作为抽取器的独立验收基准，且该验收与自动化测试分离维护。语料获取渠道与许可 〔待确认〕。事件表须支持人工修正，修正后指纹变更，下游结论随之失效——这是正确行为而非缺陷。

### 4.2 事件信息的时间可用性建模（P2）

**目的**　确保事件特征在预测起点确实可获得，杜绝比列角色错位更隐蔽的时间维度泄漏。

**方案**　强制三时间分离：事件发生时间、新闻发布时间、模型可获得时间，三者为事件表的必填字段，缺一即拒绝入库。特征构造只能使用模型可获得时间，其余两个仅用于事件研究的窗口定义。

**机制**　模型可获得时间 = 新闻发布时间 + 语料采集延迟。采集延迟由研究配置声明而非由模型推断，未声明时该事件的可获得性视为未验证，与 P1 中 `availability_type` 为 `unknown` 的数值变量走同一条降级路径：只能形成描述性证据，不得进入预测候选。这样 P2 的事件与 P1 的数值变量共用同一套可获得性资格语义，不引入第二套判定标准。

**选型理由** 〔待确认〕　候选方案 A 为只记录一个时间戳（通常是发布时间），实现最简，但事件发生早于新闻发布是常态，用发布时间做事件窗口会系统性错位；用发生时间做特征则直接构成前视泄漏。候选方案 B 为记录发生与发布两个时间，解决了窗口错位，但忽略了语料采集延迟——在实际部署中，新闻发布与系统可读之间存在不可忽略的间隔，忽略它会得到一个在回测中成立、在实盘中无法复现的结论。三时间是能同时满足「窗口定义正确」与「特征可用性真实」的最小字段集。

**代价与边界**　三时间对语料源提出要求：至少发布时间须可靠。发生时间在部分新闻中需从文本推断，其本身带不确定性，属于抽取质量问题而非建模问题，应体现在置信度中。

### 4.3 事件效应的统计识别（P2）

**目的**　在事件样本稀疏、窗口可能重叠、检验组合众多的条件下，给出不会系统性高估的事件效应证据。

**方案**　新增事件研究函数族并注册进现有工具注册表，与统计函数同一注册机制；把窗口定义、重叠处理、安慰剂检验与多重检验校正写入新 Skill 的协议 `invariants`，由编译器强制而非由模型选择。

**机制**　函数族至少覆盖：事件窗口内的异常收益/异常价差计算、重叠事件的剔除或合并规则、随机安慰剂窗口的对照分布、跨事件类型与窗口长度组合的多重检验校正、样本量与统计功效报告。功效不足时评估器返回 `need_user` 而非报告「不显著」——两者结论不同，前者是证据不足，后者是证据支持无效应，混淆会误导后续决策。

**选型理由** 〔待确认〕　候选方案 A 为直接在事件前后做均值差检验，实现最简，但不控制重叠与多重检验，在事件类型 × 窗口 × 变量的组合下必然产生假阳性；候选方案 B 为把事件作为哑变量直接加入回归，能同时处理多事件，但对模型设定敏感，且与 P1 「不输出因果结论」的非目标冲突。选择经典事件研究法加安慰剂对照，是因为它的假设最少、结论表述最保守，且安慰剂分布为「这个效应是否只是噪声」提供了直接可读的经验基准。

把多重检验校正写入协议不变式而非留给模型选择，是 §3.3 那条设计原则的直接延续：可被绕过的约束等于没有约束。

**代价与边界**　单一市场的重大事件数量有限，即便方法正确也可能长期得不到显著结论。这是数据本身的限制，须在报告中如实呈现为负结果，而非通过放宽窗口或增加检验来制造显著性——协议的 `stop_conditions` 应明确禁止后者。

### 4.4 时序防泄漏的样本外评估（P3）

**目的**　建立一套无法被误用的样本外评估协议，使「效果好」的实验结论确实来自预测能力而非信息泄漏。

**方案**　新增 `TimeSeriesSplitter` 模块，实现滚动训练/验证/测试切分；切分器对随机切分与时间倒置的折请求主动抛错拒绝，而非依赖调用方自觉。折内变换管道独立成模块，保证变换与特征选择在折内拟合、折外只应用不重新拟合。

**机制**　三道检查放在切分器与管道内部，因而可被单元测试固定为不变式：其一，每一折的训练窗口须严格早于其验证窗口；其二，折内使用的每个特征，其可获得时间须早于该折的预测起点（复用 §4.2 与 P1 的可获得性字段）；其三，任何 fit 类操作只接受训练折数据，管道在收到全量数据时拒绝执行。

**选型理由** 〔待确认〕　候选方案 A 为直接使用 sklearn 的 `TimeSeriesSplit`，实现成本最低，但它只保证索引顺序，不理解特征的可获得时间，无法拦截「用了未来才能拿到的预测值」这一类泄漏——而这恰是电力市场数据最常见的泄漏形态；候选方案 B 为在调用方按约定切分，灵活但把正确性寄托在每一处调用的自觉上，泄漏一旦发生会表现为指标异常优秀，极难事后发现。自建切分器的收益在于把领域特有的可获得性语义内建为拒绝条件，代价是需要自行覆盖 sklearn 已解决的边界情况。

**代价与边界**　切分器成为关键路径上的单点，其自身正确性须由高覆盖率的单元测试保证。滚动切分的折数与训练窗口长度存在偏差-方差权衡，其默认值须由领域判断给出而非取通用经验值。

### 4.5 预测实验的可复现与可比较（P3）

**目的**　在模型含随机性、实验组合空间远大于 EDA 的条件下，维持 P1 建立的可复现与可审计标准。

**方案**　两项措施：随机种子参数化并纳入计划指纹，模型族与统计函数走同一注册机制；引入 `ExperimentSpec` 作为高于 `EDAPlan` 的组合契约，描述特征集、折次配置、模型族、超参搜索预算与测试规则。

**机制**　种子由注册函数的参数 schema 约束默认值，模型不能自行指定——若允许模型选种子，同一计划两次执行将产生不同结果哈希，直接违反质量属性 1。`ExperimentSpec` 使协议约束的对象从「具体函数序列」上移到「实验规格的合法形态」，从而在不逐一注册组合的前提下保持权限边界。预算字段使超预算实验在编译期被拒绝，而非在运行时超时——桌面单机无 GPU，这一点是硬约束而非优化项。

模型族选型限定在纯 CPU 可训练范围：持续法与日/周朴素基线（已在 P1 以 `price_naive_baseline_benchmark` 存在，可直接复用为 P3 的误差底线）、正则化线性模型、梯度提升树。深度时序模型不在 P3 范围内 〔待确认〕，理由是其训练成本与桌面部署约束冲突，且在样本量有限时相对树模型的增益通常不足以抵消可复现性与调参成本。

**选型理由** 〔待确认〕　`ExperimentSpec` 的替代方案是继续为每种「模型 × 特征集 × 折配置」注册独立函数，其优点是完全复用 P1 的机制不需新增契约层，缺点是组合爆炸——三类模型、若干特征集与若干折配置的乘积会使注册表迅速不可维护。上移一层抽象的代价是新增一套契约及其校验逻辑，收益是权限边界的表达从枚举变为规则。这是 §3.2「代价与边界」中已预见的演进压力，在 P3 兑现。

**代价与边界**　`ExperimentSpec` 与 `EDAPlan` 是并列契约还是后者被前者包含，须在 P3 开工前决定；两者若长期并列，编译器需维护两条校验路径。含随机性的模型即便固定种子，跨库版本升级仍可能改变结果，故工具版本须纳入指纹并在库升级时主动标记历史实验为「需重验」。

### 4.6 跨实验的证据积累（P3）

**目的**　使新一轮实验能引用历史证据，避免重复劳动，同时控制多轮实验带来的验证集过拟合。

**方案**　建立以研究包指纹为主键的本地实验记录库，保存实验规格、输入快照引用、代码版本、模型参数、正负结果与限制；支持按研究问题、变量、方法、市场、时间窗口与结果状态检索。测试集解锁作为独立审批事项，与计划审批分离并记录解锁次数。

**机制**　实验库直接以 §3.6 的溯源链为索引基础，不另建标识体系。检索结果进入模型上下文时，其定位限定为**约束条件**而非**证据来源**——即用于回答「这个假设是否已被验证过」，不用于替代本轮的统计计算。评估器的四态决策与实验晋级状态关联：`accept` 对应晋级，`revise` 对应同层重试，`need_user` 与 `reject` 对应挂起或淘汰。

负结果必须落库。若只保存成功实验，实验库会产生系统性的幸存者偏差，而基于该库提出的下一轮假设将系统性地重复已被证伪的方向。

**选型理由** 〔待确认〕　候选方案 A 为不建库，每轮实验独立，实现最简但无法回答「这个变量之前试过没有」，多轮研究后重复劳动显著；候选方案 B 为引入 MLflow 一类实验跟踪框架，功能完备但引入额外运行时依赖与部署复杂度，与单机 EXE 分发形态冲突，且其溯源模型与本项目已有的指纹体系重叠。基于现有指纹自建轻量索引的理由是复用而非叠加——溯源链在 P1 已经存在，实验库只需为其加一层检索。

测试集独立解锁的设计动因是：实验库的存在会显著提高实验轮次，若不做此分离，实验库反而会加速测试集污染，使其从「最终裁决依据」退化为「另一个验证集」。

**代价与边界**　检索结果进入模型上下文存在被误用为结论的风险，须在提示与协议两处同时约束。研究包体积随实验轮次增长，清理与归档策略 〔待确认〕；实验库应保留索引与摘要，允许原始研究包按策略归档。

## 5. 三阶段技术演进路线

各阶段以引入的新技术能力划分，而非以任务量划分。每阶段须在前一阶段的出口判据满足后启动。

### P1　电价与外生变量 EDA（当前阶段）

| 项 | 内容 |
|---|---|
| 阶段目标 | 建立可靠的数据可用性核验、关系分析、结果评价与研究留痕基础，产出带约束标签的候选变量清单 |
| 技术能力 | Function Calling 计划编译、30 函数注册表、YAML 研究协议、LangGraph 中断恢复、确定性评估器、指纹溯源、PySide6 + PyInstaller 分发 |
| 剩余工作 | 真实模型 + 真实数据的两个 Skill 端到端验收；onedir 与 onefile 两种 EXE 验收；统一 `VPP_LLM_ENABLED` 与网关可用性判断的语义；把市场、单位、预测发布时间与目标定义补为显式门禁；加强桌面端的结果复核入口 |
| 主要风险 | 自动化回归通过不等于模型兼容性通过，两类验收须分别维护；元数据门禁缺位会向 P3 传导为泄漏风险 |
| 出口判据 | 真实研究问题可完成提问、方案、审批、执行、评估、报告、追问的闭环，失败时能恢复或明确停止；两种 EXE 均通过；元数据门禁生效，每个变量均有明确的可获得性资格 |

### P2　电价数据分析与新闻结合

| 项 | 内容 |
|---|---|
| 阶段目标 | 判定新闻事件是否为电价变化提供了 EDA 之外的增量证据，并把通过检验的事件特征加入候选变量池 |
| 新增技术能力 | 事件抽取与结果固化、三时间可用性建模、事件研究统计方法 |
| 需要引入 | `NewsCorpusLoader`；`EventExtractionSubagent`；事件表 Pydantic 契约（三时间必填）；事件研究函数族（窗口、重叠、安慰剂、多重检验校正）；`news-event-study` Skill 与协议；事件抽取的人工标注验收集 |
| 沿用不变 | Skill 授权机制、工具权限体系、计划编译与审批门禁、研究包结构与指纹溯源、评估器四态决策 |
| 新增风险 | 事件抽取依赖模型，其不确定性须以置信度显式承载并做准入过滤，不得与确定性统计证据混同；事件样本稀疏导致统计功效不足；多重检验膨胀 |
| 出口判据 | 事件特征具备明确的时间可用性定义、事件定义、统计检验与安慰剂对照证据；抽取器在人工标注集上的准确率达到可接受水平；事件特征获得与数值变量同口径的可获得性资格 |

### P3　电价预测

| 项 | 内容 |
|---|---|

| 新增技术能力 | 时序防泄漏切分与折内变换、含随机性模型的可复现实验、跨实验证据积累 |

## 6. 技术演进原则

后续扩展应继续遵循以下原则，它们在三个阶段中一致适用：

1. **模型负责方向，代码负责事实**：模型做意图、函数选择、计划修订与语言解释；统计量、数据处理与评价由确定性代码完成。P2 的事件抽取是唯一例外，其处理方式是隔离（结果固化 + 准入过滤）而非豁免。
2. **LangGraph 负责运行时，不负责业务算法**：Graph 保存状态与编排流程，数据与统计能力放在独立模块中。P2 的事件抽取落在数据准备内部，P3 的多折训练落在单次函数执行内部，主场景不新增分支。
3. **所有可执行能力必须注册和授权**：新增工具先定义契约、版本、结果键、权限与测试，再暴露给模型。组合空间过大时上移抽象层级（`ExperimentSpec`），而非放宽注册要求。
4. **审批边界优先于自动化**：任何扩大工具、变量、数据范围或实验预算的行为都必须回到用户门禁。P3 的测试集解锁是独立审批事项。
5. **结果必须可复现**：输入、配置、计划、Skill 与协议版本、工具版本、代码版本、运行环境与输出哈希共同构成证据链。随机性必须被显式参数化并纳入指纹，不存在未声明的随机源。
6. **失败是研究结果的一部分**：数据不足、泄漏风险、无显著关系、模型不稳定与实验未完成都需要被保存。P3 的负结果落库是实验库有效性的前提。
7. **先稳定闭环，再增加复杂度**：先完成 P1 的真实验收，再进入 P2，最后进入 P3。三阶段为严格前置关系。

测试重点包括：数据加载与对齐、30 个研究函数、计划权限、指纹门禁、LangGraph 恢复与 interrupt、评估收敛、桌面会话、模型网关与报告产物。仓库另有 `scripts/validate_phase1.py` 与 `scripts/validate_desktop_phase1.py` 用于阶段性验证。

> 本项目以 LangGraph 作为持久化研究流程运行时，以 OpenAI 兼容模型承担受约束的研究决策，以 Skill 与研究协议控制领域方法，以注册式确定性统计工具保证计算可信，并通过评估器、审计轨迹与可复现研究包形成「问题—方案—审批—执行—评价—迭代」的研究闭环；该闭环在第一阶段服务于电价与外生变量的 EDA，第二阶段扩展至新闻事件证据，第三阶段承载防泄漏的电价预测实验，三阶段共用同一套权限、溯源与门禁骨架。
