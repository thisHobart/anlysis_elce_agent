# P2 新闻事件工作台：批处理与人工复核

本次实现提供可运行的本地批处理入口，复用独立 P2 领域服务。桌面会话 Graph、外部采集 API 和正式真实模型资格测试仍未接入本入口；市场、时区、结算间隔、新闻截止点和抽取路径由调用方明确指定。

## 运行

在项目根目录执行以下合成数据示例，不访问模型或外部新闻服务：

```powershell
.\venv\Scripts\python.exe -m scripts.run_news_workbench run `
  --workspace artifacts/p2-workbench-demo `
  --news tests/fixtures/news_price/synthetic_news.jsonl `
  --prices tests/fixtures/news_price/synthetic_prices.csv `
  --market TEST_MARKET --timezone UTC --interval-minutes 30 `
  --as-of 2026-03-01T23:30:00Z --extractor rule --axis announcement
```

真实新闻显式指定 `--extractor structured-model`，使用现有模型配置和默认三趟一致性校验。规则路径只作为模板测试基线，不具有真实新闻资格。每个工作区固定一个市场时钟；首次运行创建 `market.json`，后续不允许静默更换。

`--as-of` 是新闻信息截止点。事件特征逐行使用该行时刻已经可见的信息，且不超过截止点；价格关联使用所提供的价格范围，是事后研究。价格范围与新闻截止点不是同一个概念。

## 每次运行的交付物

每次创建独立 `runs/<时间>-<随机标识>/`：

| 文件 | 用途 |
|---|---|
| `report.md` | 数据质量、事件证据、价格窗口和限制 |
| `events.json` | 事件台账，包括时间精度、置信度及状态历史 |
| `features.csv` | P1 可读数值表，含活动事件、提前公告和分物理方向量值 |
| `input-issues.json` | 坏输入行的内容、行号和失败原因 |
| `review-queue.json` | 原文、抽取结果、候选隔离、各趟结果及复核记录 |
| `package.json` | 完整机器可读结果与质量检查 |
| `manifest.json` | 完成标记、文件哈希、信息截止点和结果指纹 |

`manifest.json` 最后写入；缺少该文件的目录视为未完成。完成运行不覆盖历史结果。存在输入错误、未解决隔离或缺精确时间的短期事件时，状态为 `needs_review`，命令返回 2；正常完成返回 0。来源文件不存在、模型配置错误等任务级故障仍停止执行。

## 人工复核

从 `review-queue.json` 取得 `cache_key` 后登记决定：

```powershell
.\venv\Scripts\python.exe -m scripts.run_news_workbench review `
  --workspace artifacts/p2-workbench-demo --cache-key <待复核记录键> `
  --decision rejected --reviewer <复核人> --reason <判定依据>
```

处置支持 `accepted`、`rejected`、`corrected`。`corrected` 必须另外提供 `--candidate <JSON文件>`，文件结构为 `ModelNewsExtraction`（与模型候选相同）。修订候选仍经过原文、实体、量值和时间校验；不能通过“接受”把隔离数据直接放行。缺少精确时间的可信事实可以保留，但人工接受也不会自动赋予精确窗口资格。

字段复核不允许更换已有事件的类型或实体集合；这类操作需要另行设计事件拆分/合并裁决，当前明确报错，避免错误合并或双重计数。

复核记录保存在 SQLite 中，不修改原文。下一次 `run` 将决定作为标记为本地复核的新版本载入，它从实际复核时点起可见。旧截止点不会看到这次复核，新的全历史特征也保留复核前状态。因示例数据是历史数据，用过去的 `--as-of` 重跑时不会应用今天的复核，这是预期行为。

## 缓存与恢复

`news.sqlite3` 保存文档、抽取缓存、每次实际抽取尝试和复核审计。缓存身份包含文档内容及元信息、模型配置指纹、抽取器版本、市场时区和抽取趟数。API 密钥不参与保存；配置内容只用于计算指纹。

有效抽取和语义隔离可在重启后复用。技术错误不作为可复用缓存，下一次重新尝试。更换模型配置或抽取器版本会重新抽取。批量输入按行隔离格式错误，正常记录继续处理；基准工具保留严格加载方式，禁止悄悄跳过冻结验收数据中的坏行。

## 本次修正的研究口径

- 合并器 `1.3.0`：明确撤回是持续状态，后续遗漏不能重新继承撤回之前的旧值。
- 分析器 `2.0.0`：只计算完整窗口；对照按同刻和工作日/周末匹配且不重叠，也可选择同星期匹配。工作日/周末分类不等于市场节假日日历。
- 原始概率使用全部合格对照的经验尾部比例，不再通过重复抽样制造更多独立样本。保留旧 `permutation_*` 字段供现有消费者读取，方法记录明确标注 `empirical_control_tail`。
- 并发事件窗口保留描述统计，但限制单事件结论。没有对照基线时保留台账并给出排除原因；没有安慰剂时不声明稳定关联。
- 八周夹具仍恢复注入效应的方向和量级，但独立对照数量不足以支持原先的多重比较后显著性。金标准已同步改为不支持统计结论，价格生成参数和注入幅度未改；另有较长样本正例验证足够对照时可得到支持。
- 模型抽取器/Prompt `1.4.0`，模型输出 Schema 仍为 `1.3.0`：日期级事实进入台账，精确时间资格单独受控；标题日期与正文时刻分别引用原文证据，不拼造时间引文。
- 特征 `1.2.0`：保留旧活动特征，增加新增公告、未来已公告事件、距最近生效时间以及供给/需求/输电增减的容量分列。无事件为 0，有事件但量值缺失仍为未知。

## 真实数据验收

重复基准必须全部运行合格且逐案稳定，最终状态和退出码不再只取最后一轮；制品保留每轮结果。历史 `news_holdout` 已被用于流水线修正，明确标记为 `regression`。

正式独立验收使用新语料及第二人复核，并运行 `benchmark_real_news_extraction` 的 `--require-independent-holdout` 门禁。该门禁要求金标准声明 `evaluation_role: independent_holdout` 且 `independently_reviewed: true`；声明本身不替代真实的数据冻结和人工复核。当前仓库没有冒充新盲测集，也没有因为代码通过而宣称模型已具备生产资格。
