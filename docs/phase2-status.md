## 0. 一句话结论

**下游方法在受控数据上成立；规则抽取器在真实新闻上不合格；结构化抽取与版本逻辑已完成一轮现实场景修正，但真实模型必须按新的严格门槛重新运行，当前不能认定为生产合格。**

六个研究问题均已通过合成夹具（为测试而构造、预期结果已知的数据）验证，注入的价格效应被正确恢复，负对照未产生误报。
真实来源开发集包含 10 条中英文监管机构、政府和系统运营商短摘录；规则基线只正确处理了无关负样本，
9 条事件新闻均退化为 `unknown`。结构化模型抽取器、证据校验、时间/单位语义和隔离路径已经实现。
2026-09-03 使用 `vertexai:gemini-3.8-flash` 经 Cherry Studio 的 `prompt_json` 兼容路径完成过一次开发集运行。
该次逐案完整准确率为 80%，在旧门槛下显示 `qualified`。2026-09-06 复核发现旧门槛没有把完整字段准确率和证据完整性作为阻断条件，因此该结论已经失效；修正后的代码和门槛需要重新运行真实模型。

### 0.1 主要术语说明

本文面向技术、产品和研究评审人员。代码中的英文标识符保持不变，主要术语按以下含义使用：

| 术语 | 本文含义 |
|---|---|
| P1 / P2 | 第一阶段的电价探索性数据分析 / 第二阶段的新闻事件与电价分析 |
| EDA | 探索性数据分析（在正式建模前检查数据结构、质量和主要规律） |
| 合成夹具 | 为自动化测试构造、且预期输入和结果均已知的数据 |
| 规则基线 | 仅按预定义关键词和格式抽取新闻的基础方法，用于比较后续方法是否确有改进 |
| 金标准 | 由人工确认的正确答案，用于评价抽取结果 |
| 盲测集 | 调整规则或模型时不可见、仅在最终评价时使用的数据集 |
| `as_of` 视图 | 截至指定时点，只使用当时已经可获得信息重建的历史状态 |
| 结构化输出 | 模型按照预先定义的字段和类型返回结果，而不是返回自由文本 |
| 门禁 | 数据进入下一处理阶段前必须通过的自动校验条件 |
| 隔离 | 将不满足校验条件的记录移出价格分析，并保留原因供复核 |
| 哈希 | 根据输入计算的固定长度摘要，用于识别内容变化和验证结果一致性 |
| 召回率 | 应被识别的目标中，实际被正确识别的比例 |

#### 1.2.1 已确认问题的修复执行表

| 已确认问题 | 已执行修复 | 验收方式 |
|---|---|---|
| 证据是原文子串，却不一定支持模型填写的值 | 对资产名、数值和单位、标准时间与原文时间组成分别反向核对；只共享“电厂”等通用词不能证明资产名 | 虚构资产、870 MW 被写成 900 GW、10:00 被写成 11:00 均必须隔离 |
| 证据覆盖和逐案完整准确率不会阻止 `qualified` | 两项都改为阻断性门槛；模型或网关故障改记为技术无效，不得冒充正确隔离 | 故意去掉字段证据时，基准必须 `not_qualified` |
| 相同内容重复抓取会因取得时间不同形成假版本 | 文档版本身份不再包含首次取得时间，重复抓取保留最早可见时间 | 相同内容晚到一次后，版本数仍为 1 |
| 后来更正会改写更正前特征，撤回的值可能被旧版本填回 | 事件保存 `state_history`（状态历史），特征逐区间取当时可见版本；`cleared_fields`（明确撤回字段）禁止旧值复活 | 12:00 更正 500→350 MW 后，10:00 特征仍为 500 MW，12:00 起才为 350 MW |
| 事件生命周期和容量缺失的语义不正确 | `cancelled` 不激活；同资产 `generation_restore` 结束开放停运；无活动事件为 0，有事件但容量不明为未知 | 状态、恢复配对和容量三类回归测试 |
| 一个错误候选会丢掉同篇新闻的正确事件 | 改为候选级隔离；合法事件保留，失败候选记录独立原因 | 一正确、一无效的双候选案例必须返回 1 个事件和 1 条隔离记录 |
| 多趟抽取只比较资产集合，资产与事件互换仍可被判为一致 | 一致性指纹同时包含资产、事件类型、时间、容量、区域和状态 | 故意互换两个事件的资产后必须检出不一致 |
| 异市场单篇新闻使整批中断，长期或取消事件进入短期窗口 | 异市场文档逐篇进入 `market_mismatch` 隔离；长期、取消和无可对齐时刻的事件明示列为不分析 | 批处理不抛错，但数据质量报告必须不通过 |
| 历史快照可输出 `as_of` 之后的特征行 | 特征网格终点限制为价格范围与 `as_of` 中的较早者，契约层再拒绝未来行 | 早期 `as_of` 的最后一行必须等于其所在结算区间 |

## 3. 当前最重要的问题

按影响排序。前两条决定下一步做什么，其余决定怎么做。

### 3.1 规则基线无法覆盖真实新闻表达（最重要）

已实测：一条写实的中文停运新闻——“华能某电厂 1 号机组于今日凌晨紧急停机，影响出力约 60 万千瓦”
——输入规则抽取器后，结果会在没有异常提示的情况下被归为 **未知或无关（`unknown/irrelevant`）**。原因是区域名称为“华东”而不是 `TEST_NORTH`，
资产是中文名不是大写字母，容量单位是万千瓦不是 MW，时间是“今日凌晨”不是标准时刻。

这不是程序缺陷，而是规则基线的能力边界。代码侧已经新增结构化模型抽取路径，因此当前阻塞点不再是是否具备模型接口，
而是**选定真实模型、运行资格基准并建立盲测集**。在通过之前，规则基线仍不能承担真实新闻主路径。

### 3.2 合成数据太干净，真实开发集已经证实规则无法泛化

合成夹具含义明确、格式规整、每条只讲一件事；真实新闻含糊、重复、互相矛盾、一篇讲多件事。
新增真实来源开发集已经把这种差异量化为规则基线 0% 的事件召回率。

这一点方案里已经写明，此处只是重申：**不能把“六问全过”对外表述为“P2 可用”**。
它的准确含义是“方法在受控数据上成立”。

### 3.3 生产市场未定，会反过来影响已写好的代码

三处直接受影响：

- **相对时间和日期+当地时刻组合**依赖市场时区。同一句“次日 14:00”，按 UTC 算和按东八区算差 8 小时。
  时区已经是显式配置，抽取器与价格市场时钟不一致时会直接失败。
- **窗口长度**（现在是 1/6/24 小时）需要按真实市场频率重新评审。
- **结算间隔**由 `MarketClock.interval_minutes` 配置并要求整除一天；当前测试采用 30 分钟，不是代码硬编码的唯一取值。

### 3.4 事件量值契约已扩展，但下游仍保留兼容字段

新增 `EventMagnitude` 保留原值、单位、原文、MW 换算值和水平/变化/损失/恢复语义。
容量水平、需求水平和出力水平不会进入 `capacity_mw`；只有变化类量值向现有下游兼容字段投影。
后续仍需决定 P1 特征表何时直接消费完整量值语义。

### 3.5 事件类型集合还没冻结

燃料供应那一类写了没验证；是否需要补充燃料价格、监管处罚、市场暂停等场景，需要看过真实新闻样本再定。
**集合一变，事件身份的派生规则和金标准都要跟着改**，所以越早定越省事。

### 3.6 跨阶段门禁的归属需要评审确认

当前实现的选择是：**P2 在导出前把特征按可用时间对齐好**，交出去的表每行本身就不含未来信息，且行时间不会超过该快照的 `as_of`。
P1 那边的 `available_at` 只进质量报告的统计，不做行级过滤——它是提示，不是闸门。

如果评审决定改成由 P1 过滤，必须先给 P1 增加真实的行级门禁和回归测试，再改这一条。
若未明确该责任边界便继续开发，结果可能在不触发异常的情况下产生前视信息偏差。

## 4. 下一步取决于哪些决定

按方案第 11 节，前三条已经因为实际推进而被默认接受（评审若不认可，相应产物需要重做）：
以事件关联证据为 MVP、以合成市场和 UTC 为测试语境、以独立服务验证而不改造现有 Graph。

仍需评审并确认的事项：

1. 事件类型集合是否补充（见 3.5）。
2. 真实模型、模型版本和正式置信度门槛。
3. 盲测集规模、双人复核规则和生产准入阈值。
4. 跨阶段门禁放哪一边（见 3.6）。
5. 生产市场、时区与结算间隔（见 3.3）。
6. 首个产品出口是离线报告、桌面交互，还是定时生成的证据包。
