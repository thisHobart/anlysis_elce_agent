# 电价分析 Agent 技术框架与开发路线

> 文档用途：项目汇报、技术评审和后续开发协同  
> 适用版本：当前桌面端研究 Agent 代码  
> 当前定位：电价与外生变量 EDA Agent MVP  
> 更新日期：2026-08-26

## 1. 项目概述

### 1.1 项目目标

本项目面向电价研究场景，构建一个由大模型辅助、确定性统计工具负责计算、LangGraph 负责流程编排的研究型 Agent。用户用自然语言提出研究问题，Agent 结合数据画像推荐分析方案；用户可以确认或调整方案；系统随后调用受约束的统计函数执行分析，并对结果进行结构化评价、补充规划和可复现归档。

项目的长期目标是从“电价与外生变量探索”逐步演进到“预测实验、新闻事件研究和跨域研究闭环”。当前版本聚焦第一阶段：先建立可靠的数据体检、关系分析、结果评价和研究留痕基础。

### 1.2 当前阶段结论

当前项目已经具备一个可运行的桌面研究 Agent MVP，主要能力包括：

- PySide6 三栏桌面工作台，统一承载历史会话、连续对话、数据文件和研究过程。
- DeepSeek 与自定义 OpenAI 兼容接口接入能力。
- 主 Agent 对用户回合进行对话路由，EDA Subagent 根据研究问题和数据画像提出结构化分析方案。
- 通过 Skill 和本地研究协议约束研究顺序、工具权限和停止条件。
- 通过工具注册表、权限策略和确定性执行器调用本地统计函数，禁止模型直接执行任意 Python 或自由代码。
- 方案审批、自然语言修订、逐函数执行、结果校验、确定性评估和有限自动修订。
- 记录计划版本、数据指纹、工具版本、执行时间、结果哈希和运行轨迹。
- 输出自包含 HTML 报告、Markdown 报告、SVG 图表和结构化 JSON/Parquet 研究包。
- 使用 LangGraph checkpoint 支持审批、执行异常和结果交互后的恢复。

当前仍属于 EDA 阶段，不包含正式预测模型训练、新闻事件抽取、因果识别和跨实验历史库。最近一次功能升级后，真实模型、真实数据和 Windows EXE 需要重新进行完整验收；仓库中的验收记录说明自动化回归曾达到 `142 passed`，但该数字应以升级后的最新复验结果为准。

### 2.1 架构分层

┌────────────────────────────────────────────────────────────┐
│                    PySide6 Desktop UI                     │
│  历史会话 │ 连续对话 │ 方案卡 │ 研究过程 │ 数据文件 │ 结果卡 │

                        │
                        ▼
┌────────────────────────────────────────────────────────────┐
│              ResearchCoordinator 应用协调层                │
│  会话投影、Graph 调用、进度叙述、模型配置、结果回填          │
└───────────────────────┬────────────────────────────────────┘
                        │
                        ▼
┌────────────────────────────────────────────────────────────┐
│              LangGraph ResearchLoopGraph                   │
│  理解问题 → 选择 Skill → 生成计划 → 校验 → 审批 interrupt   │

└─────────────┬──────────────────────┬───────────────────────┘
              │                      │
              ▼                      ▼
┌────────────────────────┐  ┌──────────────────────────────┐
│ LLM 协作层              │  │ 确定性研究执行层              │
│ MainResearchAgent       │  │ StudyConfig / Data Loader      │
│ EDASubagent             │  │ Alignment / Quality / Snapshot │
│ Shared Model Gateway    │  │ Plan Compiler                  │
└─────────────┬──────────┘  │ ToolRegistry / Policy / Executor│

### 2.2 核心职责划分

| 层次 | 主要职责 | 不负责的内容 |
|---|---|---|
| 桌面交互层 | 展示会话、接收问题、选择文件、确认方案、展示过程和报告入口 | 不直接计算统计量，不直接决定研究顺序 |
| LangGraph 编排层 | 管理状态、节点路由、interrupt/resume、循环、恢复和终止 | 不替代统计函数，不产生业务数据 |
| LLM 协作层 | 理解意图、选择 Skill、提出函数调用、修订方案、解释结构化证据 | 不执行任意代码，不直接生成统计结果，不保存私有思考链 |
| Skill/协议层 | 描述领域研究顺序、授权函数、阶段目标、门禁和停止条件 | 不提供任意可执行脚本 |
| 规划与安全层 | 编译模型方案、校验函数、参数、变量、版本和授权边界 | 不绕过用户审批执行计划 |
| 数据与统计层 | 读取、对齐、质量检查和执行确定性分析 | 不让模型自由拼接 SQL/Python |
| 评估与报告层 | 评价证据、生成后续建议、沉淀可复现研究包 | 不把相关性自动解释为因果关系 |

其中，LangGraph 是当前 Agent 的流程运行时和状态编排核心；`app/llm` 是模型供应商接入边界；`app/research/tools/eda` 是统计计算核心。三者职责分离，避免把“模型调用、工作流控制和统计实现”混在一个模块中。

## 3. 当前已实现能力

### 3.1 桌面研究工作台

入口为 `python -m app.desktop`，Windows 用户也可以双击 `start_desktop.bat`。当前界面采用单一三栏连续研究会话：

| 区域 | 已实现能力 |
|---|---|
| 左侧历史研究 | 新建、搜索、选择、重命名、删除会话；删除会话时同步删除对应 Graph 线程，已生成的报告文件保留 |
| 中间连续对话 | 用户问题、助手回复、方案卡、研究过程卡、结果卡和追问处于同一时间线 |
| 右侧上下文 | 选择研究配置、目标电价、实际外生变量、预测外生变量，并查看数据状态和完整运行轨迹 |
| 模型配置 | DeepSeek 官方接口、自定义 OpenAI 兼容接口、Base URL、API Key、模型名、超时、重试和历史消息数配置 |
| 运行控制 | 方案确认、自然语言修改、30 秒反馈窗口、停止当前任务、结果追问和会话重启恢复 |

当前不再以 FastAPI、Nginx 或 Docker 作为项目运行入口，主要产品形态是本地桌面应用；原有服务端部署文件已从当前项目路径中移除。

### 3.2 大模型接入与 Agent 协作

模型接入集中在 `app/llm`：

- `ModelGateway` 定义供应商无关的结构化输出、文本输出和 Function Calling 契约。
- `OpenAICompatibleGateway` 通过 `langchain-openai` 创建懒加载的 `ChatOpenAI` 客户端。
- `factory.py` 为主 Agent 和 EDA Subagent 注入同一个模型网关，避免每个 Agent 各自维护连接。
- 支持 DeepSeek 官方 Base URL 和自定义 OpenAI 兼容 Base URL。
- 通过 `extra_body` 关闭 thinking，并对 `reasoning_content`、reasoning block 和 `<think>` 内容执行 fail-closed 检查。
- 结构化计划固定使用 Function Calling；模型返回无效调用、空回复或非授权内容时，流程暂停并提示重试。

当前 Agent 角色划分如下：

1. `MainResearchAgent`：判断当前回合是方法讨论、新建方案、修订方案、结果解释还是执行确认。
2. `EDASubagent`：在当前 Skill 授权范围内选择具体 EDA 函数并形成结构化计划。
3. `ResearchCoordinator`：将桌面事件转换为 Graph 输入，接收状态更新并投影到会话界面。

### 3.3 Skill 与研究协议

项目当前内置两个研究 Skill：

| Skill | 版本 | 适用范围 | 工具范围 |
|---|---:|---|---:|
| `price-exogenous-eda` | 3.0.0 | 电价与外生变量联合 EDA | 30 个原子研究函数 |
| `price-forecastability-audit` | 1.0.0 | 只有目标电价或先判断电价自身可预测性 | 14 个电价侧函数 |

Skill 由 `SKILL.md` 和版本化 YAML 研究协议组成。协议固定阶段顺序、阶段目标、函数集合、函数规则和退出门槛；模型只在授权集合中选择函数，不能通过提示词改变本地权限。

`price-exogenous-eda` 当前的证据顺序为：

1. 市场时钟与研究范围
2. 数据体检
3. 电价自身规律
4. 外生变量质量
5. 电价与外生变量关系证据
6. 可预测性准备度

外部 Skill 可以通过程序同级 `skills/` 或 `VPP_SKILL_PATHS` 加载，但外部 Skill 不能自动注册或执行任意脚本。

### 3.4 数据接入、对齐与质量检查

当前支持 CSV 和 Parquet，数据通过研究配置或桌面文件槽位加载。四类输入角色为：

| 角色 | 说明 | 执行要求 |
|---|---|---|
| 研究配置 | YAML，描述市场、时区、频率、列名、单位和分析参数 | 可选；没有时可由界面自动识别部分字段 |
| 目标电价 | 目标时间序列 | 真正执行分析时必需 |
| 实际外生变量 | 负荷、新能源、发电、备用等实际值 | 可选；适合描述性分析 |
| 预测外生变量 | 发电、新能源、水电等预测值 | 可选；必须确认预测发布时间和可获得性 |

数据层已实现：

- 时间戳解析、时区统一、数值转换和非法记录识别。
- 统一时间网格、重采样和目标/外生变量对齐。
- 覆盖率、缺口、重复时间戳、无效数值、异常值和可获得时间风险检查。
- 对齐后的标准分析帧供规划、工具执行和最终评估复用。
- 输入文件清单和 SHA-256 指纹；方案生成后文件被原地修改时拒绝继续执行旧方案。

当前默认配置为 `configs/research/price_exogenous_eda.yaml`，示例使用 `15min` 频率和 `Asia/Shanghai` 时区，市场名称和单位仍标记为待补充元数据。

### 3.5 确定性 EDA 工具箱

当前工具注册表包含 30 个原子研究函数，按五类组织：

| 类别 | 主要能力 |
|---|---|
| 数据体检 | 时间对齐、覆盖率、缺失、重复、数值有效性和可获得性风险 |
| 电价自身规律 | 分布、持续曲线、极端值、负价、尖峰状态、日历规律、滚动波动、平稳性、趋势季节分解、自相关、偏自相关、分段比较 |
| 外生变量质量 | 分布、IQR 异常值、长期漂移、两两相关、VIF、驱动平稳性 |
| 关系证据 | Pearson、Spearman、领先滞后、互信息、Granger 样本内前置性、分小时/月份、分位响应、滚动稳定性、分段比较 |
| 可预测性准备度 | 方差稳定变换检查、持续法/日朴素/周朴素基线 |

工具执行链为：

```text
模型 Function Call
→ EDAPlan
→ Planning Compiler
→ ToolRegistry
→ ToolPolicy
→ ToolExecutor
→ numpy/pandas/scipy/statsmodels 确定性函数
→ ToolResult
```

关键安全约束包括：

- 工具名必须来自注册表，版本必须匹配。
- 变量名必须来自当前研究配置，目标序列不能冒充外生变量。
- 每个函数在一个计划中最多出现一次；多变量、多滞后和多分段通过批量参数完成。
- `data_quality` 由编译器强制加入。
- 模型不能提供函数路径、任意 Python、SQL 或未注册参数。
- 负价和尖峰作为市场现象保留，不静默删除或截尾。
- 相关性、互信息、Granger 和分组差异只作为描述性证据，不自动等同于因果或样本外预测增益。

### 3.6 LangGraph 持久化研究循环

桌面端当前通过一个 `ResearchLoopGraph` 统一承载研究过程。循环状态分为四层：

```text
Session
└── Episode：一个独立研究目标
    └── Iteration：计划 → 执行 → 校验 → 评估
        └── Stage attempt：规划尝试或函数调用尝试
```

主流程为：

```text
接收问题
→ 主 Agent 路由
→ 创建 Episode
→ 解析 Skill
→ EDA Subagent 生成计划
→ 计划编译与校验
→ interrupt 等待用户审批
→ 锁定计划和工具队列
→ 逐函数执行与结果校验
→ 确定性评估
→ 接受 / 自动修订 / 请求用户 / 拒绝
→ 解释结果、生成报告或进入下一轮
```

已实现的运行时机制包括：

- `interrupt/resume` 实现方案审批和结果交互。
- SQLite checkpoint 保存 Graph 权威运行状态；测试场景可使用内存 saver。
- `Command(resume=...)` 恢复用户操作，非法 action 不改变原 checkpoint。
- 方案审批同时校验方案 ID、方案指纹和审批事实，模型意图不能绕过审批。
- 规划失败、函数重试和崩溃恢复与已完成评估 Iteration 分开计数。
- 自动修订只能在原审批范围内收缩工具、变量或滞后；扩大范围必须回到用户门禁。
- 通过 `call_id`、`work_id`、数据指纹和输出哈希实现执行溯源与确定性结果复用。
- Graph 事件、消息和运行历史有界保存，完整桌面轨迹由会话投影保留。

### 3.7 结果评估与研究报告

评估器 `app/research/evaluation/eda.py` 不依赖模型直接给出最终判定，而是根据结构化工具证据检查：

- 数据是否足以支持当前研究。
- 计划中的关键证据是否已产生。
- 假设是否得到支持、不支持或证据不足。
- 是否存在可在原审批范围内修订的问题。
- 是否需要补充数据或用户确认。
- 结论是否触及方法论固有限制。

评估决策为 `accept`、`revise`、`need_user` 和 `reject`。报告包默认写入用户文档目录，也可以通过 `PRICE_RESEARCH_OUTPUT_DIRECTORY` 覆盖。

一次 Agent 研究包通常包含：

```text
agent-<timestamp>-<fingerprint>/
├── report.html              # 自包含主报告，内联 SVG
├── report.md                # Markdown 版本
├── figures/*.svg            # 图表源文件
├── conversation.json       # 对话记录
├── research_plan.json      # 计划、Skill、协议、版本和参数
├── execution_trace.json    # 函数执行时间和结果引用
├── study_config.json       # 解析后的研究配置
├── data_quality.json       # 数据质量证据
├── eda_summary.json        # 完整结构化分析结果
├── agent_evaluation.json   # 评估结论和反馈
├── research_loop.json      # 循环上下文
├── aligned_data.parquet   # 固定的对齐数据快照
└── manifest.json           # 输入/输出哈希、Git 和运行环境
```

## 6. 当前版本的边界与待完善项

### 6.1 已明确的产品边界

- 当前是离线本地文件研究工具，不是 Web 服务。
- 当前输出是描述性 EDA 和预测准备度证据，不是正式预测结果。
- 朴素基线只用于误差量级参考，后续预测实验仍需滚动时间切分。
- Granger、相关、互信息和分组差异不等同于因果结论。
- 预测变量必须补齐发布时间、可获得时间和预测起点后，才适合进入预测实验。
- 市场名称、单位字典和业务语义仍需要由领域人员确认。

### 6.2 近期应优先处理的问题

1. **完成升级后的真实验收**：覆盖两个内置 Skill、真实模型、真实数据、桌面重启恢复、HTML 报告和 EXE。
2. **统一 LLM 开关语义**：当前配置仍保留 `VPP_LLM_ENABLED`，但模型网关的可用性主要由 Base URL 和模型名判断；后续应统一确认启用开关、界面状态和运行时判断。
3. **完善元数据校验**：市场、单位、预测发布时间、可获得性和目标定义应在进入预测阶段前变成显式门禁。
4. **分离测试替身与真实验收**：自动化测试证明边界和确定性逻辑，真实模型验收证明 Function Calling、模型兼容性和桌面体验，两者需要分别维护。
5. **加强结果复核入口**：报告查看、结果 JSON、运行轨迹和输入指纹应在桌面端形成更直接的打开/复制/定位操作。

## 7. 后续开发路线

### 阶段 0：MVP 稳定化与验收闭环

**目标**：把当前 EDA Agent 从“代码功能完成”推进到“真实使用可交付”。

**主要工作**：

- 完成真实模型 + 真实数据的两个 Skill 端到端验收。
- 验证模型配置、thinking 关闭、Function Calling 和失败提示。
- 验证桌面会话恢复、30 秒审批、停止、删除会话和结果追问。
- 验证 30 个函数的代表性场景、报告 HTML 排版和 SVG 图表。
- 验证 onedir EXE，再验证 onefile EXE；确认内置 Skill 和用户目录可写。
- 补齐市场、单位和可获得性元数据示例。

**阶段出口**：真实研究问题可以完成“提问 → 方案 → 审批 → 执行 → 评估 → 报告 → 追问”闭环，且失败时能恢复或明确停止。

### 阶段 1：预测基线与外生变量增量实验

**目标**：从 EDA 证据进入可比较的预测实验，但保持严格的时间顺序和数据防泄漏。

**主要工作**：

- 增加持续法、日朴素、周朴素和简单线性/树模型基线。
- 实现滚动训练、验证和测试切分，禁止随机切分时间序列。
- 比较“仅历史电价”和“历史电价 + 外生变量”的增量效果。
- 在每个训练折内完成变换、缺失处理和特征选择。
- 按小时、月份、峰谷、尖峰和负价状态输出分组误差。
- 保存每次实验的参数、折次、误差、稳定性、失败原因和负结果。

**阶段出口**：任何候选外生变量只有在同折、同预算、同测试规则下超过基线，才可进入下一步特征实验。

### 阶段 2：新闻事件与事件研究

**目标**：引入新闻或外部事件，研究事件信息是否对电价变化提供增量证据。

**主要工作**：

- 区分事件发生时间、新闻发布时间和模型可获得时间。
- 抽取事件类型、实体、区域、方向、强度和置信度。
- 实现事件窗口、重叠事件、安慰剂窗口和多重检验控制。
- 对比无新闻基线与加入事件特征后的增量表现。
- 将事件证据接入现有 Skill、工具权限和研究包。

**阶段出口**：新闻特征拥有明确的时间可用性、事件定义、统计检验和样本外验证证据。

### 阶段 3：评估器与历史实验库

**目标**：让 Agent 能基于历史研究结果提出更有约束的下一轮研究。

**主要工作**：

- 建立实验记录库，保存实验规格、输入快照、代码版本、模型参数、正负结果和限制。
- 支持按研究问题、变量、方法、市场、时间窗口和结果状态检索。
- 增加数据泄漏、样本外稳定性、统计显著性、多重比较和业务可解释性门禁。
- 将 `accept / revise / reject / need_user` 与实验晋级状态关联。
- 对验证集和最终测试集实施锁定，降低多轮研究导致的验证过拟合。

**阶段出口**：新的研究计划能够引用历史证据，并能解释为什么复用、舍弃或重新验证某个假设。

### 阶段 4：跨域研究 Agent

**目标**：从单一 EDA Agent 演进为可扩展的跨域研究 Agent。

**主要工作**：

- 用统一的 `ExperimentSpec` 描述 EDA、预测、事件研究和特征实验。
- 将历史实验检索、假设生成、实验规划、执行和评价纳入同一 LangGraph 循环。
- 为不同研究领域加载独立 Skill，但继续共享统一模型网关、状态协议、工具权限和报告结构。
- 增加预算、重复假设检测、证据收敛和停止条件。
- 只在单域流程稳定后，再引入更多模型供应商、远程工具或 MCP 类外部工具。

**阶段出口**：Agent 能提出下一轮受约束实验，引用历史证据，执行可复现计算，并在证据不足时主动请求用户或数据，而不是无限循环。

## 8. 技术演进原则

后续扩展应继续遵循以下原则：

1. **模型负责方向，代码负责事实**：模型做意图、函数选择、计划修订和语言解释；统计量、数据处理和评价由确定性代码完成。
2. **LangGraph 负责运行时，不负责业务算法**：Graph 保存状态和编排流程，数据与统计能力放在独立模块中。
3. **所有可执行能力必须注册和授权**：新增工具先定义契约、版本、结果键、权限和测试，再暴露给模型。
4. **审批边界优先于自动化**：任何扩大工具、变量、数据范围或实验预算的行为都必须回到用户门禁。
5. **结果必须可复现**：输入、配置、计划、Skill、工具版本、代码版本、运行环境和输出哈希共同构成证据链。
6. **失败是研究结果的一部分**：数据不足、泄漏风险、无显著关系、模型不稳定和实验未完成都需要被保存，而不是只保留成功结论。
7. **先稳定闭环，再增加复杂度**：先完成单域 EDA 的真实验收，再扩展预测、新闻、历史实验库和跨域 Agent。

.\build_exe.bat

.\build_exe.bat --onefile
