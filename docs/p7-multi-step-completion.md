### 1. Mock API 服务 ✅

**文件**: `app/services/vpp_api_mock.py`

- `companies` - 企业列表查询（支持按名称、ID、类型筛选）
- `realtime-load` - 企业实时负荷查询

### 2. 多步查询编排 ✅

**文件**: `app/graph/nodes/query_data.py`

实现了 `_execute_multi_step_query()` 函数，支持：

**Step 1: 实体提取**
- 从用户问题中提取企业名称
- 支持多种企业名称模式（带/不带后缀）

**Step 2: 企业ID查询**
- 优先使用 API 查询企业ID
- API 失败时回退到数据库
- 精确匹配企业名称

**Step 3: 企业数据查询**
- 根据 FAQ 类型调用不同的 API
- FAQ-09: 查询企业实时负荷
- FAQ-15: 查询企业可调能力

## 架构设计

### 混合式查询架构

```
用户问题
    ↓
分类节点 (classify)
    ↓
路由到 FAQ (FAQ-09/FAQ-15)
    ↓
query_data 节点
    ↓
检测多步编排需求
    ↓
_execute_multi_step_query()
    ↓
Step 1: 提取企业名 (正则)
    ↓
Step 2: 查询企业ID (Mock API → DB fallback)
    ↓
Step 3: 查询企业数据 (Mock API)
    ↓
返回结构化数据
    ↓
compose 节点填充模板
    ↓
返回最终答案
```

### 数据流

**FAQ-09 示例**: "山东鲁能新能源的实时负荷是多少？"

1. **提取实体**: "山东鲁能新能源"
2. **查询企业ID**: 
   - API: `companies?name=山东鲁能新能源` → `company_id: "COMP001"`
3. **查询实时负荷**: 
   - API: `realtime-load?company_id=COMP001` → `{load: 1234.56, ratio: 78.5}`
4. **返回数据**: 
   ```python
   {
       "enterprise_name": "山东鲁能新能源",
       "load": 1234.56,
       "ratio": 78.5
   }
   ```
5. **填充模板**: "山东鲁能新能源当前实时负荷为1234.56千瓦，占其可调能力的78.5%。"

## 技术亮点

1. **确定性数据处理**
   - 不使用 LLM 进行数据查询和转换
   - 保证数据准确性和安全性

2. **优雅的降级策略**
   - API 优先 → DB 回退
   - 多步骤中任何一步失败都能优雅处理

3. **可扩展设计**
   - 易于添加新的 FAQ（FAQ-16, FAQ-17...）
   - 易于扩展其他依赖链模式

4. **Mock API 开发模式**
   - 在真实 API 未就绪时可以完整开发和测试
   - Mock 数据结构与真实 API 保持一致
   - 后续只需切换 API endpoint
